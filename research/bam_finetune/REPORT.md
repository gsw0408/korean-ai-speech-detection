# 편집 경계 분할기 비교 실험 보고서 — BAM 재학습 확정 (2026-10-25)

## 결론
**한국어 편집 데이터로 재학습한 BAM(경계 기준값 0.5)을 분할기로 확정합니다.**

- 지시대로 기준을 넘은 시점에 BDR 학습은 중단했습니다(22/40 에포크, 평가 안 함).

재학습 BAM의 고정 4초 창 대비 AUC 향상(녹음 묶음 bootstrap 2,000회, 95% CI): **1초 +0.133 [0.066, 0.184], 2초 +0.151 [0.117, 0.186]**. 두 구간 모두 하한이 0보다 큽니다. 정답 경계 상한과의 차이는 1초 0.035, 2초 0.020으로, **상한에 거의 도달**했습니다.

## 사전 기준 (결과를 보기 전에 고정)
- **K1:** 1초·2초 삽입 각각(쉼·말 중간·PartialSpoof 유사 방식 합산)에서, "분할 → NII" AUC가 고정 4초 창보다 높아야 합니다. 녹음 묶음 bootstrap 95% CI 하한이 0보다 커야 합니다. 설계 문서의 G2를 AUC로 바꾼 것입니다.
- **K2:** 편집 경계 적중률(±0.3초, AI·사람 삽입 합산) 0.70 이상, 편집 없는 파일의 헛경계 10초당 2개 이하.
- **판정 기준값 고정:** BAM·BDR은 0.5, TRACE는 z 2.0. 다른 기준값은 참고용입니다. 참고로 재학습 BAM은 0.1과 0.3에서도 통과했습니다.

## 실험 설정
- **데이터:** Dataset v2 **TRAIN만** 사용. 진짜 음성 녹음 묶음을 해시로 나눠 학습용 52개 / 평가용 13개로 분리했고, 겹치는 묶음은 0개입니다.
  - 학습: 합성 파일 2,930개(9.5시간). AI 삽입 1,356 / 사람 삽입 1,356 / 편집 없음 218. 편집 방식(쉼·말 중간·PartialSpoof 유사)과 삽입 길이(0.5~3초)는 무작위입니다.
  - 평가: 780개(2.3시간). 60쌍 × 편집 방식 3 × 길이 1·2초 × AI·사람 삽입, 그리고 편집 없음 60개입니다.
- **정답:** AI 삽입이든 사람 삽입이든 **편집 지점은 모두 경계**로 표시했습니다. 진위 판정은 NII가 맡습니다.
- **BAM 재학습:** 10/16에 고정한 공식 BAM 소스·체크포인트(WavLM-Large, 160ms)에서 시작했습니다. Adam 1e-5, 6에포크, 배치 8, 4초 조각(80%는 경계 포함), 경계 손실 가중치 1.0, fp16. **마지막 에포크를 그대로 사용**했고, 평가 데이터로 체크포인트를 고르지 않았습니다.
  - 경계 손실(에포크별): 0.366 → 0.112 → 0.076 → 0.052 → 0.041 → 0.030
- **TRACE:** NII-Small 고정 임베딩(마지막 층, 6층)에서 0.3초 좌우 평균 코사인 거리로 경계 점수를 내고, 파일 안에서 z점수로 바꿨습니다. 학습은 없습니다.
- **판정:** 분할된 구간 중 0.5초 이상을 모두 NII(가변 길이, 배포 모델과 같은 가중치)로 채점했습니다. 파일 점수는 구간 최댓값입니다. AUC는 AI 삽입 파일 vs 같은 위치에 사람 음성을 삽입한 파일입니다.
- **환경:** AWS 서울 g5.xlarge(A10G). 학습 13분, 경계 추출 2분, 평가 9분이 걸렸습니다.

## 해석
1. **원인 분석 결과와 일치합니다.** 공개 BAM이 못 찾던 경계를, 한국어 대화 편집 데이터로 6에포크만 재학습해도 95% 이상 찾게 됐습니다. 문제는 모델 구조가 아니라 학습 데이터였다는 판단이 맞았습니다.
2. **"분할 → NII 판정" 구조가 실제로 효과가 있습니다.** 짧은 삽입에서 지금 방식보다 AUC가 0.13~0.17 높고, 정답 경계로 자른 상한과의 차이는 0.02~0.04입니다.
3. **TRACE(학습 없음)는 효과가 없었습니다.** NII 임베딩의 급변만으로는 한국어 대화의 자연스러운 변화와 편집을 구분하지 못했습니다(헛경계 10초당 2.6~4.1개).
4. **1초 삽입은 여전히 어렵습니다.** 정답 경계로 잘라도 AUC가 0.73~0.78입니다. 분할기의 한계가 아니라 **NII가 1초 조각을 판정하는 능력의 한계**입니다. 앞선 상한 시험의 0.84와 같은 흐름입니다.

## 한계 (반드시 함께 보고)
- **평가 데이터의 생성기가 학습과 같습니다.** 평가용 AI 삽입도 Supertonic·XTTS·RVC입니다. 녹음 묶음은 분리했지만, **처음 보는 생성기**에 대한 경계 탐지 성능은 시험하지 않았습니다.
- 합성 방식이 단순합니다(0.3초 쉼, 10ms 이음, 바로 붙이기). 실제 편집기·신경망 음성 편집으로 만든 편집은 포함하지 않았습니다.
- 평가 데이터는 녹음 묶음 13개, 60쌍이라 신뢰구간이 넓습니다(조건별 ±0.05~0.1).
- 학습 seed 1개, 고정 레시피 1개로 했고, 반복 실험은 하지 않았습니다.
- **서비스 적용 전 과제:** WavLM-Large 기반이라 CPU에서 120초 파일에 약 2분, 메모리 8GB 이상이 듭니다(10/16 측정). 지금 서버(4 vCPU, 목표 30초·2.5GB)에 그대로 올릴 수 없습니다. 서비스용으로는 경량화(작은 모델로 증류, 또는 BDR처럼 wav2vec2-base 기반 모델)가 필요합니다.
- TRACE의 6층 특징은 마지막 층보다 1프레임(20ms) 길게 나와, 경계 위치에 최대 20ms 오차가 있을 수 있습니다.
- 고정 4초 창의 "헛경계" 값은 창 경계를 센 것이라 의미가 없어 표에서 뺐습니다.

## 추가 실험: 경량 후보 BDR (2026-10-25)
**목적:** BAM보다 가벼운 모델이 비슷한 성능을 내면 그 모델을 채택합니다.

**채택 조건(결과를 보기 전 고정)**
1. K1·K2 통과
2. 재학습 BAM 대비 1초·2초 AUC 차이의 95% CI 하한이 −0.05보다 큼(비열등성)
3. CPU 4스레드에서 120초 파일 30초 이내, 메모리 2.5GB 이하

**설정**
- `speechbrain_PartialFake` 공식 구조: wav2vec2-base-960h → MelResNet → Transformer, 1.28초 창
- 앞단까지 함께 미세조정했습니다. 공개 BDR 체크포인트는 Google Drive에서 받지 못해서, wav2vec2-base-960h에서 출발했습니다.
- 원래 레시피의 MUSAN/RIR 증강은 뺐습니다. Adam 1e-4, Noam(1,600 step) 스케줄, 40에포크(1,720 step), 마지막 에포크 사용
- 학습 데이터, 평가 데이터, NII 판정 방식은 BAM과 동일합니다.

**결과: 채택하지 않음**

| 항목 | BDR(0.5) | 재학습 BAM(0.5) |
|---|---:|---:|
| 1초 AUC | 0.559 | 0.728 |
| 2초 AUC | 0.632 | 0.887 |
| BAM 대비 차이(1초 / 2초) | −0.170 [−0.233, −0.099] / −0.255 [−0.318, −0.196] | — |
| 경계 적중률(±0.3초) | 0.00 | 0.958 |
| CPU 120초 처리(4스레드, 3회) | 52.8~53.1초 | 측정 실패(아래 참고) |
| 최대 메모리 | 2.07GB | — |

- **학습 실패로 판단합니다.** BDR의 경계 확률은 모든 평가 파일에서 최대 0.12를 넘지 않았습니다(중앙값 0.09). 거의 일정한 값만 내고 경계를 표시하지 못했습니다.
- **원인(추정):** Noam 스케줄의 워밍업(1,600 step)이 전체 학습(1,720 step)과 거의 같아서 학습률이 충분히 올라가기 전에 학습이 끝났습니다. 공개 레시피는 200에포크이고, 사전학습된 BDR 체크포인트도 쓰지 못했습니다. 그래서 **이 결과는 "BDR 구조가 안 된다"가 아니라 "이번 레시피로는 학습이 덜 됐다"**는 뜻입니다.
- **서비스 비용도 기준을 넘었습니다.** 학습이 잘 됐다고 해도, 지금 방식(1.3초 창, 50% 겹침, 120초당 창 약 186개)으로는 CPU 53초가 걸려 목표(30초)를 넘습니다. 겹침을 줄이거나 ONNX로 바꾸는 등의 경량화가 필요합니다.
- **BAM CPU 측정은 실패했습니다.** 120초 파일을 통째로 넣는 방식이 메모리 부족(16GB 서버에서 약 15GB 사용 후 강제 종료)으로 끝나지 않았습니다. 10/16 측정(4초 창 방식)에서는 120초 파일에 약 118초, 메모리 8.3GB였습니다. **BAM을 서비스에 쓰려면 창 단위 처리와 경량화가 반드시 필요합니다.**

**결론:** 가벼운 대안이 조건을 넘지 못했으므로 **재학습 BAM 확정을 유지**합니다. 남은 경량 후보는 "NII 특징 + 경계 판정부"(추가 앞단 없음)와, 레시피를 고친 BDR(더 긴 학습, 사전학습 체크포인트 확보)입니다.
